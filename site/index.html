03贯穿全程的设计原则

这些不是口号——每一条都有对应的代码实现和测试断言锁死。

源每句话都有出处

事实携带「表名+行号+编号」，成句携带事实编号，打印稿翻译回真实出处。测试断言：无出处句子必被质检拦截。

核先抽取、后成文，中间代码核对

模型只负责理解和组织语言；出处存在、药名在原文、剂量数值等价——三步逐字核对由代码完成，对不上剔除并留痕。

算算术交给代码

住院天数、最高体温、发热统计由「计算器节点」算出，口径即常量（37.3℃ 阈值只改一处），计算事实带依据与出处。

拒fail-closed

核对未实现时全部剔除；没验证过的内容不能出口。宁可草稿为空，不可让未核对的话混进病历。

检测试锁不变式

消防演习：注入「说谎的抽取模型」和「说谎的书记员」，断言闸门拦截、草稿不收、评估如实记账。锁的是不变式，不是某次输出。

批批准是显式动作

数据外发批准 = 环境变量 DRCOPILOT_DATA_APPROVED=1，不是聊天里说一句可以。自动化评估 ≠ 自动化批准：批量稿一律驳回归档。

座模型是可换插座

规则基线 ↔ 真模型（OpenAI 兼容）经工厂切换，流程代码零改动；切换由批准闸门把关。换厂商只改配置。

回回归验证与保回归

重构只许动结构不许动行为——旧输出是行为规格（第 9 课数字一字不差）；「防雪崩上限」这类保险也要在评估里验证没杀召回（第 8 课）。

🔴 数据安全铁律（任何时候不能违反）

  1. 真实数据永不入库、不上传：git 仓库只放代码与文档，`.gitignore` 拦截数据格式；推送前执行姓名/住院号反向扫描（本站发布时实测命中 0）。
  2. 开发教学一律用脱敏/虚构数据：真实姓名 → 测试患者甲～戊；真名映射表仅存本地受控位置。
  3. 云端追踪强制关闭：LangSmith 等 4 个追踪环境变量在代码最前面写死为 false。
  4. API key 只从环境变量读取：绝不写进代码；数据外发需显式批准环境变量。
  5. 出口闸门：每次调用模型前扫描手机号/证件号/长编号/禁用姓名，命中即停、模型零调用，报警单自身打码。

解覆盖率 33%~80% 怎么解读

缺口集中在吸入用七氟烷（5/5）与罗哌卡因（4/5）——麻醉用药由麻醉医生术中给药，不走普通医嘱表。 这是数据源缺口，不是模型问题；对策是接入手术/麻醉记录数据源。

解多报 343 条怎么解读

草稿有、标准答案没有——常见原因是普通溶媒（氯化钠/葡萄糖）本就不单独写用药记录。 多报交医生判断，不自动定罪；这是「标准答案只覆盖特殊用药」的体现。

解编造 0 条意味着什么

不是运气：出处不存在、药名不在原文、结果值被篡改——任一不过即被剔除，有测试作证。 这是架构的可证明安全性质，对医疗系统是底线要求。
