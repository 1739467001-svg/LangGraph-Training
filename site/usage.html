07四种工作模式

按场景选择。所有命令在 src/ 目录下执行。

运行命令

cd src
python3 -m medrecord.run 测试患者甲 批准

第一个参数是患者文件夹名，第二个是医生审核结论（批准 / 驳回）。即第 03 节终端实况里的命令。

流程会经过什么

闸门 → 计算器 → 32 个工位并行抽取 → 核对 → 书记员 3 栏目分批成文 → 编号质检 → 暂停在审核站 → 按给定结论恢复 → 打印稿 + XML + 评估落盘。

换患者、换结论

python3 -m medrecord.run 测试患者丙 批准
python3 -m medrecord.run 测试患者甲 驳回   # 草稿归档，标注「不得作为正式病历」

真实医院场景：提交系统和医生审核隔着一台机器、一个夜晚。存档落盘（SQLite），两个独立进程接力。

护士站
（系统）
→
python3 -m medrecord.submit 测试患者乙

跑完抽取核对 → 挂在审核站 → 进程退出。存档 outputs/checkpoints.sqlite， thread_id：medrecord-测试患者乙

→
overnight

草稿睡在磁盘里；get_state() 可查看挂起位置与待审材料

→
医生站
（次日）
→
python3 -m medrecord.review 测试患者乙 批准

新进程从磁盘读回草稿 → 医生表态 → 从暂停点继续 → 评估报告落盘。 「批准」出正式稿，「驳回」归档并警示。

要点：恢复不是重放——抽取与核对不会重跑；医生看到的就是暂停时那份。 同一张图可同时挂起多位患者（thread_id 隔离）。

python3 -m medrecord.batch          # 全部患者；也可 run_batch(["测试患者乙"])

它做什么

编译一次图，按 thread_id 顺序跑全部患者；每位患者自动完成评估；产出 outputs/批量验收报告.md（汇总表 + 自动解读）。

治理规则（重要）

批量评估的草稿一律走「驳回」归档——自动化评估 ≠ 自动化批准。 批准永远是医生的显式动作，这条规则有测试断言锁着。

怎么读报告

覆盖率必须连同「未覆盖原因」一起汇报。实测缺口：吸入用七氟烷（5/5 患者）、 罗哌卡因（4/5）不走医嘱表——是麻醉数据源缺口，对策是接入手术/麻醉记录。

python3 -m pytest -q            # 全部 61 项，约 5 秒
python3 -m pytest medrecord/tests/test_write_section.py -v   # 单文件详情

测试都在保护什么

核对闸门（出处/名称/数值篡改必拦）、说谎模型与说谎书记员注入演习（编造必拦）、 归并规则（重写不累积）、治理规则（批量稿必归档）、出口闸门（拦截时模型零调用）。

什么时候跑

改提示词后、换模型后、动任何节点后——提交前必跑。61 项 ≈ 5 秒， 改坏了 5 秒内就知道。

文件清单（全部在 outputs/，git 忽略）

文件谁写的内容与用途
{患者}_病历草稿.mdrender 节点 给医生看的打印稿：状态横幅（已过审/未过审）、住院概况表、三栏目成文句（真实出处）、质控记录
lesson13_{患者}_文书草稿.xmlexport_eval 结构化草稿（对接医院系统的中间格式；真实 DCSoft 模板到位后按模板回填）
批量验收报告.mdbatch 五患者汇总表 + 自动解读（覆盖率区间、未覆盖药物、成文/计算统计）
checkpoints.sqlitesubmit/review 审核存档（thread_id 隔离；含 -shm/-wal 伴生文件）

评估报告三个指标怎么读

覆盖率
命中的标准答案药物种数 ÷ 标准答案种数（医生写的用药记录）。 必须连同未覆盖原因汇报：实测缺口（七氟烷 5/5、罗哌卡因 4/5）是麻醉数据源缺口，不是模型问题。
多报
草稿有、标准答案没有——常见原因是普通溶媒（氯化钠/葡萄糖）本就不单独写用药记录。 多报交医生判断，不自动定罪。
编造
核对剔除数（出处不存在/名称不符/数值篡改）。 实测五患者 0 条进入草稿——架构的可证明性质，61 项测试作证。
打印稿怎么核
每句后括号里的出处可直接回查：打开对应 xlsx 的第 N 行核对原文。 「待医生补充」= 该栏目无核对通过的事实，需医生手工补写。

09接入真模型

模型是插座：规则基线 ↔ 真模型切换只动环境变量，流程代码零改动。未批准时系统自动退回基线。

环境变量必填说明
DRCOPILOT_API_KEY是厂商 API key，只放环境变量，绝不写进代码或提交 git
DRCOPILOT_MODEL是模型名，如 glm-4-flash / deepseek-chat
DRCOPILOT_LLM_BASE_URL按厂商OpenAI 兼容端点（智谱 / DeepSeek / Qwen 等均兼容）
DRCOPILOT_DATA_APPROVED批准时设必须等于 1——这就是数据外发的显式批准，缺它系统自动退回基线
批准的语义：清洗后的数据包含真实临床内容。把 DRCOPILOT_DATA_APPROVED 设为 1 之前， 系统物理上不可能把数据发给任何厂商——这条纪律有测试锁死（未批准时工厂只返回基线）。

上线后建议先跑 A/B：同一患者分别以基线与真模型运行，对比评估报告三指标。 比较三点：核对剔除率、成文质检退回率、速度与成本。

10故障排查（本项目实测过的问题）

InvalidUpdateErrorAt key 'facts': Can receive only one value per step
原因：多个并行工位同时写同一个状态字段，且该字段没有归并规则。 修复：把 State 字段改为 Annotated[list, operator.add]（追加合并）。 若需「重写前清空」，参考 written_reducer 的 __RESET__ 标记模式（第 20 课）。
网络git push 报 HTTP2 framing layer / Empty reply / 连接超时
原因：到 github.com 的 443 端口间歇性阻断（api.github.com 可能仍通）。 修复：① 多重试几次（本机实测第 3~6 次成功）；② git -c http.version=HTTP/1.1 push； ③ 换 SSH over 443：ssh://git@ssh.github.com:443/用户名/仓库.git（需先注册 SSH key）。
ModuleNotFoundErrorNo module named 'medrecord'
原因：不在 src/ 目录下运行，或缺少根目录 pytest.ini。 修复：流水线命令用 cd src && python3 -m medrecord.run …； 测试在项目根目录跑 python3 -m pytest -q（根目录 pytest.ini 已配置 pythonpath=src）。
TypeError'MedicationFact' object is not subscriptable
原因：结构化输出返回的是 pydantic 对象列表，直接按字典下标取值。 修复：先 [f.model_dump() for f in result.facts] 再按 dict 使用。
流程不停没有触发医生审核暂停
排查：① doctor_review 节点内确实调用了 interrupt(...)； ② build_main_graph 传入了 checkpointer；③ 恢复时用同一个 thread_id 与同一个存档器；④ 恢复用 Command(resume=结论)。
数据缺失检查/检验/概况栏目没有内容
排查：① 患者文件夹里对应 xlsx 是否存在（装载器对缺失文件静默跳过）； ② 检查所见依赖 IMPRESSION 列、检验所见依赖 RESULT 列，全空的行会被跳过； ③ 体温值在 VITAL_SIGNS_CVALUES 列，不在 VALUES 列。
gitgit status 出现病历资料/ 清洗后的数据/
这是最高优先级问题。修复：确认项目根目录有 .gitignore 且包含 病历资料/、清洗后的数据/、outputs/、deid_tools/mapping_真实值勿提交.json； 若已暂存：git rm -r --cached 病历资料/ 后重新提交。推送前跑姓名/住院号反向扫描是固定工序。
评估异常覆盖率突然从 80% 掉到 0%
按第 8 课的闭环走：评估 → 追查 → 修复 → 复测。本项目实测原因： 工位内「最多 8 条」截断上限把排在后面的药物静默丢掉。教训：任何防出事的上限， 都要验证它没有杀召回。
